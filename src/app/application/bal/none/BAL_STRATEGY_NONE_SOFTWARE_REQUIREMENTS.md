# BAL 无均衡策略 — 软件需求规格说明

### 1.1 目的

## 2. 总体描述

### 2.1 产品视角

`bal_strategy_none.c` 是 BAL 模块的**策略模式（Strategy Pattern）**架构下的一个具体策略实现。当硬件平台不具备电池均衡能力（即均衡 IC 不支持均衡功能）时，编译链接此文件以提供符合 BAL 接口的占位实现，确保上层调用代码无需修改即可正常运行。

```
BMS 应用层
    │
    ▼
BAL 主模块 (bal.c)
    │
    ├── bal_strategy_voltage.c  ← 电压均衡策略（真实实现）
    ├── bal_strategy_none.c     ← 无均衡策略（本模块，占位实现）
    └── ...                     ← 其他策略
```

### 2.2 工作模式

模块仅有一种工作模式：**占位模式**（Dummy Mode）。

- 所有接口调用均立即返回成功
- 不执行任何均衡相关操作
- 不维护任何内部状态

### 2.3 适用场景

- 硬件平台无均衡 IC
- 均衡功能被永久禁用
- 开发和调试阶段需要一个无副作用的均衡模块占位

**处理流程**：
1. 函数被调用
2. 直接返回 `STD_OK`

**前置条件**：无

**后置条件**：无（纯函数，无副作用）

**错误处理**：无。本策略下不存在初始化失败的情况。

### 3.2 状态请求处理

#### REQ-002 — 无条件接受所有状态请求

- **优先级**：高
- **函数**：`BAL_SetStateRequest()`

**描述**：系统应提供状态请求设置接口。在无均衡策略下，该接口接受所有类型的状态请求（如初始化请求、错误请求、均衡使能/禁用请求等），并始终返回 `BAL_OK`，但**不执行任何实际操作**。

**输入**：

| 参数 | 类型 | 说明 |
|------|------|------|
| `stateRequest` | `BAL_STATE_REQUEST_e` | 期望设置的状态请求（被忽略） |

**输出**：

| 返回值 | 含义 |
|--------|------|
| `BAL_OK` | 请求已接受（本策略始终返回此值） |

**处理流程**：
1. 函数被调用，传入 `stateRequest` 参数
2. 使用 `(void)stateRequest` 显式抑制编译器"未使用参数"警告
3. 返回 `BAL_OK`

**前置条件**：无

**后置条件**：无。不修改任何全局状态或硬件寄存器。

**错误处理**：无。所有请求类型均被视为合法。

**处理流程**：

**前置条件**：无
