# SOC 调试模块 — 软件需求规格说明

## 1. 引言

### 1.1 目的

本文档规定了 foxBMS 2 电池管理系统中 **SOC 调试**模块
（[soc_debug.c](soc_debug.c)）的功能和非功能需求。
该模块是 SOC 算法接口的一个轻量级调试/桩实现，用于在开发和测试阶段
提供最小化的 SOC 功能替代，而不依赖真实的电流传感器、FRAM 或电池模型。

### 1.2 范围

SOC 调试模块涵盖以下内容：

- 提供与完整 SOC 实现相同的公共 API 接口
- 对输入参数进行基本断言校验
- 为电压-SOC 转换提供固定的默认返回值

本模块**不**涵盖以下内容：

- 真实的库仑计数或电流积分
- 基于电压查表的 SOC 重校准
- 非易失存储器（FRAM）读写
- 充放电吞吐量累积
- SOC 范围限制与钳位
- 任何形式的真实 SOC 计算

### 1.3 定义与缩略语

| 术语 | 定义 |
|------|------|
| **SOC** | 荷电状态（State-of-Charge），以电池串标称容量的百分比 [0%, 100%] 表示 |
| **BMS** | 电池管理系统（Battery Management System） |
| **BS_NR_OF_STRINGS** | 系统中电池串的数量 |
| **调试变体（Debug Variant）** | SOC 模块的一种实现，提供桩/空操作行为，用于测试和开发 |
| **桩（Stub）** | 一个提供固定或空操作行为的函数实现，替代真实逻辑 |
| **FAS_ASSERT** | foxBMS 断言宏，在调试构建中若条件为假则中止执行 |

## 2. 总体描述

### 2.1 产品视角

SOC 调试模块是 foxBMS 2 中几种可互换的 SOC 算法实现之一。其他实现包括：

- **库仑计数变体**（[soc_counting.c](../counting/)）—— 完整的电流积分 SOC 估算
- **查表变体**（[soc_lookup-table.c](../lookup-table/)）—— 基于电压-SOC 查表的 SOC 估算
- **空变体**（[soc_none.c](../none/)）—— 不接受任何外部数据的空操作实现
- **调试变体**（[soc_debug.c](soc_debug.c)）—— 本模块，用于调试目的的桩实现

该模块通过构建配置（wscript）在编译时选定。它由状态估算封装层
（[state_estimation.c](../state_estimation.c)）调用，封装层持有 SOC 数据库块
并调用 SOC 函数。调试变体提供了与其他变体相同的公共 API 签名，
但不执行任何真实的 SOC 计算。

### 2.2 设计意图

调试变体旨在满足以下使用场景：

1. **硬件无关的开发与测试：** 在不需要真实电池或电流传感器的环境中，
   允许 BMS 固件编译和运行。
2. **接口验证：** 提供一种确认 SOC API 调用顺序和参数传递正确性的方法。
3. **回归测试基线：** 作为最简单可能的 SOC 实现，提供一个已知行为（固定输出）
   的参考点，用于测试上层调用逻辑。
4. **快速原型开发：** 在 SOC 算法未就绪时，允许系统的其他部分进行集成和测试。

### 2.3 用户特征

本模块供以下用户使用：

- 固件开发人员，在对上层应用逻辑进行单元测试时需要桩 SOC 实现
- 集成测试工程师，需要隔离 SOC 算法以测试其他子系统
- 持续集成（CI）流水线，在没有硬件传感器可用的环境中执行自动化测试

## 3. 功能需求

### 3.1 SOC 初始化

#### FR-3.1.1 — 桩初始化

**编号：** FR-3.1.1
**优先级：** 中
**函数：** `SE_InitializeStateOfCharge()`

**描述：**
模块应提供一个 `SE_InitializeStateOfCharge()` 的桩实现，
该函数仅对输入参数进行断言校验，不执行任何实际的 SOC 初始化操作。
不访问 FRAM，不设置任何内部状态，不填充 SOC 值。

**输入：**

| 参数 | 类型 | 描述 |
|------|------|------|
| `pSocValues` | `DATA_BLOCK_SOC_s *` | 指向 SOC 数据库块的指针 |
| `ccPresent` | `bool` | 如果硬件库仑计数器传感器可用则为 `true`；否则为 `false`（未使用） |
| `stringNumber` | `uint8_t` | 电池串索引 [0, `BS_NR_OF_STRINGS` - 1] |

**前置条件：**

- `pSocValues` 不得为 NULL
- `stringNumber` 必须小于 `BS_NR_OF_STRINGS`

**处理流程：**

1. 断言 `pSocValues` 不为 NULL
2. 断言 `stringNumber` 小于 `BS_NR_OF_STRINGS`
3. 返回（无其他操作）

**后置条件：**

- 无。SOC 数据库块内容不会被修改。
- 不设置任何初始化完成标志。
- 不访问 FRAM 或其他硬件。

**错误处理：**

- 如果 `pSocValues` 为 NULL，断言失败
- 如果 `stringNumber >= BS_NR_OF_STRINGS`，断言失败

> **设计说明：** 完整的实现（如库仑计数变体）会从 FRAM 恢复 SOC 值，
> 设置 CC 缩放基准，初始化时间戳，并标记模块为已初始化。
> 调试变体有意省略了所有这些步骤。

---

### 3.2 SOC 计算

#### FR-3.2.1 — 桩 SOC 计算

**编号：** FR-3.2.1
**优先级：** 中
**函数：** `SE_CalculateStateOfCharge()`

**描述：**
模块应提供一个 `SE_CalculateStateOfCharge()` 的桩实现，
该函数仅对输入参数进行断言校验，不执行任何实际的 SOC 计算。
不读取电流传感器数据，不更新 SOC 值，不写入 FRAM。

**输入：**

| 参数 | 类型 | 描述 |
|------|------|------|
| `pSocValues` | `DATA_BLOCK_SOC_s *` | 指向 SOC 数据库块的指针 |

**前置条件：**

- `pSocValues` 不得为 NULL

**处理流程：**

1. 断言 `pSocValues` 不为 NULL
2. 返回（无其他操作）

**后置条件：**

- 无。SOC 数据库块内容不会被修改。
- 不执行静置重校准。
- 不执行库仑计数或电流积分。
- 不累积充放电吞吐量。
- 不写入 FRAM。

**错误处理：**

- 如果 `pSocValues` 为 NULL，断言失败

> **设计说明：** 完整的实现会检查电池系统状态，执行静置重校准或库仑计数，
> 并更新 SOC 值。调试变体有意省略了所有这些步骤。值得注意的是，
> 与库仑计数变体不同，调试变体也**不**执行初始化守卫检查
> （因调试变体中不存在初始化完成标志）。

---

### 3.3 电压-SOC 转换

#### FR-3.3.1 — 固定电压-SOC 映射

**编号：** FR-3.3.1
**优先级：** 中
**函数：** `SE_GetStateOfChargeFromVoltage()`

**描述：**
模块应提供一个电压-SOC 转换函数，该函数忽略输入的电压值，
始终返回固定的 SOC 值 **50.0%**（`0.50f`）。

**输入：**

| 参数 | 类型 | 描述 |
|------|------|------|
| `voltage_mV` | `int16_t` | 电池电压，单位为毫伏（被忽略） |

**返回值：**

| 类型 | 描述 |
|------|------|
| `float_t` | 固定值 `0.50f`（即 50.0% SOC） |

**前置条件：**

- 无

**处理流程：**

1. 返回常量 `0.50f`

**后置条件：**

- 返回值始终为 0.50（50.0%），与输入电压无关

**错误处理：**

- 无。该函数不执行任何可能导致错误的条件检查或计算。

> **设计说明：** 选择 50.0% 作为固定返回值是一个中性的默认值，
> 表示电池处于半满状态。在完整实现中，此函数使用电压-SOC 查表
> 进行线性插值以确定真实的 SOC。调试变体中返回固定值确保上层调用方
> 接收到一个定义明确的、有效的 SOC 值（在 [0.0, 100.0] 范围内），
> 不会因未初始化的 LUT 数据而崩溃或产生未定义行为。

## 4. 非功能需求

### 4.1 时序与性能

#### NFR-4.1.1 — 确定性执行时间

**编号：** NFR-4.1.1
**优先级：** 高

所有三个公共函数应具有**常数时间**执行复杂度 O(1)。
具体而言：

- `SE_InitializeStateOfCharge()`：仅执行两次整数比较断言，无循环，无外部调用
- `SE_CalculateStateOfCharge()`：仅执行一次指针断言，无循环，无外部调用
- `SE_GetStateOfChargeFromVoltage()`：仅执行一次 `return` 语句

任何函数的执行时间均不依赖于输入数据或系统状态。
这确保调试变体不会引入时序抖动，这对调试和测试场景至关重要。

#### NFR-4.1.2 — 零外部依赖调用

**编号：** NFR-4.1.2
**优先级：** 高

模块不得调用任何外部模块的函数（`FAS_ASSERT` 除外，该宏在发布构建中
可能被编译为空）。特别禁止调用：
- 数据库读写函数
- FRAM 读写函数
- 数学插值函数
- BMS 状态查询函数
- 电池配置访问函数

---

### 4.2 内存

#### NFR-4.2.1 — 零静态内存占用

**编号：** NFR-4.2.1
**优先级：** 高

模块不得声明任何静态变量或文件作用域变量。
具体而言，不应存在以下内容：
- 模块内部状态结构体
- 数据库表的本地副本
- 每串电池的跟踪数组
- 任何形式的持久化状态

这确保了调试变体在内存占用方面具有绝对的最小开销，
适用于内存受限的测试环境。

#### NFR-4.2.2 — 零栈内存开销

**编号：** NFR-4.2.2
**优先级：** 中

函数不得分配任何非平凡的栈变量（如本地数组或大型结构体）。
每个函数的栈帧应仅包含调用约定的最小开销。

---

### 4.3 鲁棒性

#### NFR-4.3.1 — 基于断言的参数校验

**编号：** NFR-4.3.1
**优先级：** 高

所有接受指针或索引参数的公开函数应使用 `FAS_ASSERT()` 校验关键前提条件：

- `SE_InitializeStateOfCharge()`：校验 `pSocValues != NULL` 和 `stringNumber < BS_NR_OF_STRINGS`
- `SE_CalculateStateOfCharge()`：校验 `pSocValues != NULL`

`SE_GetStateOfChargeFromVoltage()` 不接受指针或索引参数，因此无需断言。

#### NFR-4.3.2 — 无未定义行为路径

**编号：** NFR-4.3.2
**优先级：** 高

所有执行路径必须明确定义，无未定义行为：
- 无条件分支，不依赖未初始化变量
- 无可能导致除零的操作
- 无可能导致数组越界的操作
- 无空指针解引用（由断言防止）

### 4.4 兼容性

#### NFR-4.4.1 — API 签名兼容性

**编号：** NFR-4.4.1
**优先级：** 高

模块必须提供与所有其他 SOC 变体**完全一致**的公共 API 签名：

| 函数 | 签名 |
|------|------|
| `SE_InitializeStateOfCharge()` | `void SE_InitializeStateOfCharge(DATA_BLOCK_SOC_s *, bool, uint8_t)` |
| `SE_CalculateStateOfCharge()` | `void SE_CalculateStateOfCharge(DATA_BLOCK_SOC_s *)` |
| `SE_GetStateOfChargeFromVoltage()` | `float_t SE_GetStateOfChargeFromVoltage(int16_t)` |

所有函数返回值类型、参数类型和参数顺序必须与
[state_estimation.h](../state_estimation.h) 中的声明完全匹配。

#### NFR-4.4.2 — 构建系统兼容性

**编号：** NFR-4.4.2
**优先级：** 高

模块必须通过 [wscript](wscript) 构建脚本在编译时可选择。
当通过构建配置选择时，此变体必须替换所有其他 SOC 变体
（实现具有唯一性，不与库仑计数或其他变体同时链接）。

#### NFR-4.4.3 — 单元测试框架兼容性

**编号：** NFR-4.4.3
**优先级：** 低

当使用 `UNITY_UNIT_TEST` 编译时，模块应能通过编译。
目前调试变体在 `UNITY_UNIT_TEST` 条件下未暴露任何额外的测试函数
（`#ifdef UNITY_UNIT_TEST` 块为空），这在当前形态下是预期行为。

---

### 4.5 可维护性

#### NFR-4.5.1 — 代码简洁性

**编号：** NFR-4.5.1
**优先级：** 中

调试变体应保持绝对最简实现：
- 所有三个函数的实际代码（不含注释和空行）不超过 12 行
- 不包含条件编译块（除空的单元测试块外）
- 每个函数仅包含断言调用和最终返回语句

这使得调试变体易于审查，且能清晰地表明它是有意的桩实现。

## 7. 使用约束

### 7.1 适用场景

- ✅ 软件开发阶段，SOC 算法尚未实现或集成
- ✅ 不依赖硬件在环（HIL）的自动化单元测试
- ✅ 持续集成（CI）流水线中的编译验证
- ✅ 上层状态估算逻辑的接口测试
- ✅ 在没有电池系统可用的环境中进行固件集成测试

### 7.2 不适用场景

- ❌ 需要真实 SOC 估算的生产部署
- ❌ 硬件在环（HIL）测试（需使用库仑计数变体或查表变体）
- ❌ 电池系统带有真实电流/电压传感器的任何场景
- ❌ SOC 精度验证测试
- ❌ 充放电策略依赖于准确 SOC 值的任何场景
