## 概述

本规范旨在为 C 语言安全编码提供明确、可强制执行的检查标准。编码标准鼓励程序员遵守由项目和组织需求决定的统一规则和准则，而不是依赖程序员的个人喜好或习惯。本规范适用于：

- **C99 标准**（ISO/IEC 9899-1999）及其技术勘误 TC1、TC2
- ISO/IEC TR 24731-1 边界检查接口
- POSIX 兼容和 Windows 操作系统环境

## 规范体系说明

### 规则（Rules）vs 建议（Recommendations）

| 类型 | 说明 | 合规性要求 |
|------|------|-----------|
| **规则（Rules）** | 违反将导致可利用的安全漏洞；有可验证的符合性 | **必须遵守**，合规声明需满足所有规则 |
| **建议（Recommendations）** | 改善系统安全的指南，未能满足规则的一个或多个条件 | 非强制，建议采纳 |

### 标识符格式

每个规则和建议具有唯一标识符，格式为：

```
XXX##-A/C
```

- `XXX`：三字母类别助记符（如 PRE、DCL、EXP）
- `##`：两位数字（00-29 为建议，30-99 为规则）
- `A`：建议（Advisory），`C`：规则（Compulsory）

---

## 优先级与等级

优先级基于 FMECA（失效模式、影响及关键性分析）方法，三个维度评分均为 1-3 分：

| 维度 | 1分 | 2分 | 3分 |
|------|-----|-----|-----|
| **严重性（Severity）** | 低（拒绝服务、异常终止） | 中（数据完整性破坏、信息泄露） | 高（执行任意代码） |
| **可能性（Likelihood）** | 不太可能 | 可能 | 很可能 |
| **修复代价（Remediation Cost）** | 高（手动检测修复） | 中（自动检测/手动修复） | 低（自动检测修复） |

三项乘积（1-27）决定等级：

| 等级 | 乘积范围 | 说明 |
|------|---------|------|
| **Level 1**（最高） | 12-27 | 必须优先修复 |
| **Level 2** | 6-9 | 重要，尽快修复 |
| **Level 3** | 1-4 | 一般，酌情修复 |

## 01. 预处理器（PRE）

### 建议

#### PRE00-A. 优先使用内联函数替代宏

宏的使用类似函数调用，但具有不同的语义，容易引发安全隐患。C99 引入了内联函数，应尽量用内联函数替代宏。

**❌ 不合规示例**
```c
#define CUBE(X) ((X) * (X) * (X))
int i = 2;
int a = 81 / CUBE(++i);  // 展开为 ++i * ++i * ++i，未定义行为
```

**✅ 合规方案**
```c
inline int cube(int i) {
    return i * i * i;
}
int i = 2;
int a = 81 / cube(++i);  // 副作用只执行一次
```

> **例外**：宏不能总是被内联函数替代，例如：实现泛型函数（模拟C++模板）、惰性求值（如 `SELECT(s, v1, v2)`）、编译时常量表达式等场景。

| 严重性 | 可能性 | 修复代价 | 优先级 | 等级 |
|--------|--------|---------|--------|------|
| 1（低） | 1（不太可能） | 2（中） | P2 | L3 |

---

#### PRE01-A. 宏定义中对变量名使用括号

宏定义中所有变量名均应加括号，防止运算符优先级问题。

**❌ 不合规示例**
```c
#define CUBE(I) (I * I * I)
int a = 81 / CUBE(2 + 1);  // 展开为 (2 + 1 * 2 + 1 * 2 + 1) = 11，错误
```

**✅ 合规方案**
```c
#define CUBE(I) ((I) * (I) * (I))
int a = 81 / CUBE(2 + 1);  // 展开为 ((2+1)*(2+1)*(2+1)) = 27，正确
```

| 严重性 | 可能性 | 修复代价 | 优先级 | 等级 |
|--------|--------|---------|--------|------|
| 1（低） | 1（不太可能） | 3（低） | P3 | L3 |

---

#### PRE02-A. 函数式宏展开结果必须用括号括起

函数式宏的展开结果应始终用括号括起，防止低优先级运算符被周围表达式影响。

**❌ 不合规示例**
```c
#define CUBE(X) (X) * (X) * (X)
int a = 81 / CUBE(i);  // 展开为 81 / i * i * i = 243，错误
```

**✅ 合规方案**
```c
#define CUBE(X) ((X) * (X) * (X))
int a = 81 / CUBE(i);  // 展开为 81 / (i*i*i) = 3，正确
```

| 严重性 | 可能性 | 修复代价 | 优先级 | 等级 |
|--------|--------|---------|--------|------|
| 1（低） | 1（不太可能） | 3（低） | P3 | L3 |

---

#### PRE03-A. 避免在调用函数时误调用宏

程序员可能无意中调用了函数式宏而不是实际函数。应通过 `#undef` 或加括号的方式避免。

**❌ 不合规示例**
```c
// 库定义了 #define abs(x) _BUILTIN_abs(x)
// 程序员想调用自己实现的 abs，但宏会被展开
int result = abs(-5);
```

**✅ 合规方案**
```c
// 通过括号禁止宏展开，强制调用真实函数
int result = (abs)(-5);
```

| 严重性 | 可能性 | 修复代价 | 优先级 | 等级 |
|--------|--------|---------|--------|------|
| 1（低） | 1（不太可能） | 1（高） | P1 | L3 |

---

#### PRE04-A. 不要重用标准头文件名

不得创建与标准库头文件同名的文件，否则会导致包含错误的头文件。

**❌ 不合规示例**
```c
// 创建了名为 stdio.h 的自定义头文件
#include "stdio.h"  // 可能包含自定义版本而非标准库
```

| 严重性 | 可能性 | 修复代价 | 优先级 | 等级 |
|--------|--------|---------|--------|------|
| 1（低） | 1（不太可能） | 3（低） | P3 | L3 |

---

### 规则

#### PRE30-C. 不要通过拼接创建通用字符名（Universal Character Name）

不得通过宏拼接（`##`）操作符创建通用字符名（`\uXXXX` 或 `\UXXXXXXXX`）。

| 严重性 | 可能性 | 修复代价 | 优先级 | 等级 |
|--------|--------|---------|--------|------|
| 1（低） | 1（不太可能） | 1（高） | P1 | L3 |

## 02. 声明与初始化（DCL）

### 建议

#### DCL00-A. 用 const 限定不变对象

将不需要修改的对象声明为 `const`，可让编译器帮助检测误修改行为。

**✅ 合规示例**
```c
const int max_count = 100;
void process(const char *input);
```

---

#### DCL01-A. 不要在子作用域中重用变量名

避免在内层作用域中声明与外层作用域同名的变量，防止遮蔽（shadowing）问题。

**❌ 不合规示例**
```c
int count = 0;
void func(void) {
    int count = 0;  // 遮蔽了全局变量 count
    count++;
}
```

**✅ 合规方案**
```c
int g_count = 0;
void func(void) {
    int local_count = 0;
    local_count++;
}
```

---

#### DCL04-A. 每次声明只声明一个变量

避免在同一行声明多个变量，降低声明指针时出错的风险。

**❌ 不合规示例**
```c
char *src, c;   // src 是指针，c 是 char，易混淆
int x, y, *z;
```

**✅ 合规方案**
```c
char *src;
char c;
```

---

### 规则

#### DCL30-C. 声明对象时使用正确的存储类

对象的存储期必须足够长，以覆盖其所有使用场景，不得返回局部变量的指针或引用。

**❌ 不合规示例**
```c
const char *error_msg(int error_num) {
    char msg[64];
    snprintf(msg, sizeof(msg), "Error %d", error_num);
    return msg;  // 返回局部变量地址，未定义行为
}
```

**✅ 合规方案**
```c
const char *error_msg(int error_num) {
    static char msg[64];
    snprintf(msg, sizeof(msg), "Error %d", error_num);
    return msg;
}
```

---

#### DCL31-C. 使用前必须先声明标识符

所有标识符在使用前必须显式声明，禁止依赖隐式函数声明。

**❌ 不合规示例**
```c
int main(void) {
    int x = add(1, 2);  // add 未声明
    return 0;
}
```

---

#### DCL32-C. 保证唯一可见

外部链接的标识符在整个程序中必须唯一，防止链接时的命名冲突。

---

#### DCL33-C. 确保函数声明中 restrict 限定的指针不指向同一对象

使用 `restrict` 限定的指针参数必须确保实际调用时不指向重叠内存区域。

---

## 03. 表达式（EXP）

### 建议

#### EXP00-A. 使用括号明确运算符优先级

在复杂表达式中使用括号明确运算顺序，避免依赖对优先级的记忆。

**❌ 不合规示例**
```c
if (a & b == 0)   // 实际为 a & (b == 0)，不是 (a & b) == 0
```

**✅ 合规方案**
```c
if ((a & b) == 0)
```

---

#### EXP01-A. 不要对指针取 sizeof

`sizeof(ptr)` 返回的是指针本身的大小，而非所指向的对象大小。

**❌ 不合规示例**
```c
char *str = malloc(n);
memset(str, 0, sizeof(str));  // 只清零指针大小（4或8字节），而非缓冲区
```

**✅ 合规方案**
```c
memset(str, 0, n);
```

---

### 规则

#### EXP30-C. 不要依赖序列点之间的求值顺序

C 语言未规定同一个表达式中多个子表达式的求值顺序，不得依赖此顺序。

**❌ 不合规示例**
```c
int i = 5;
int a = i++ + i++;    // 未定义行为
int b = func() + func2();  // 两个函数的调用顺序未定义
```

---

#### EXP32-C. 不要通过指向限定类型的非限定指针访问 volatile 对象

访问 `volatile` 变量必须通过 `volatile` 限定的指针，否则可能被编译器优化掉。

---

#### EXP33-C. 不要读取未初始化的内存

使用未初始化变量是未定义行为，可能导致不可预测的程序状态。

**❌ 不合规示例**
```c
int x;
printf("%d\n", x);  // x 未初始化
```

---

#### EXP34-C. 确保空指针解引用不会发生

对指针解引用前必须检查其是否为 NULL。

**❌ 不合规示例**
```c
char *p = malloc(n);
*p = 'a';  // 未检查 malloc 是否返回 NULL
```

**✅ 合规方案**
```c
char *p = malloc(n);
if (p == NULL) {
    /* 错误处理 */
    return -1;
}
*p = 'a';
```

## 04. 整数（INT）

### 建议

#### INT00-A. 理解数据模型对整数大小的影响

不同平台（ILP32、LP64、LLP64等）中 `int`、`long`、`pointer` 的大小不同，应使用固定宽度类型（`int32_t`、`uint64_t` 等）。

---

#### INT01-A. 使用 rsize_t 或 size_t 表示对象大小

使用 `size_t` 或 `rsize_t` 表示内存大小和数组索引，确保足够大且无符号。

---

### 规则

#### INT30-C. 确保无符号整数运算不发生回绕

无符号整数在溢出时会回绕（wrap around），需在运算前进行检查。

**❌ 不合规示例**
```c
unsigned int a = UINT_MAX;
unsigned int b = a + 1;  // 回绕为 0
```

**✅ 合规方案**
```c
if (a > UINT_MAX - 1) {
    /* 处理溢出 */
}
unsigned int b = a + 1;
```

---

#### INT31-C. 确保整数转换不会丢失或解释错误

整数类型转换时，若值超出目标类型范围，结果为实现定义行为。

**❌ 不合规示例**
```c
int si = INT_MAX;
unsigned int ui = si;  // 在有些平台上结果未定义
char c = 260;          // 值丢失
```

---

#### INT32-C. 确保有符号整数操作不溢出

有符号整数溢出是未定义行为，不同于无符号整数回绕。

**❌ 不合规示例**
```c
int a = INT_MAX;
int b = a + 1;  // 未定义行为
```

**✅ 合规方案**
```c
if (a > INT_MAX - 1) {
    /* 处理溢出 */
}
int b = a + 1;
```

---

#### INT33-C. 确保除法和取模运算不产生未定义行为

除数为零或有符号整数 `INT_MIN / -1` 均为未定义行为。

**✅ 合规方案**
```c
if (divisor == 0 || (dividend == INT_MIN && divisor == -1)) {
    /* 处理错误 */
} else {
    result = dividend / divisor;
}
```

---

#### INT35-C. 对于整数类型的位运算，使用正确的精度

位运算结果依赖整数宽度，应使用固定宽度整数类型，并注意符号扩展问题。

---

## 05. 浮点数（FLP）

### 建议

#### FLP00-A. 理解浮点数的局限性

浮点数（`float`、`double`）无法精确表示许多十进制数，计算结果可能有精度误差。

---

#### FLP01-A. 注意浮点-整数转换的精度问题

将浮点数转换为整数时会截断小数部分；反向转换时可能因精度不足而无法精确表示。

---

### 规则

#### FLP30-C. 不要在浮点循环计数器中使用浮点变量

浮点数精度误差可能导致循环次数不准确。

**❌ 不合规示例**
```c
for (float f = 0.1f; f != 1.0f; f += 0.1f) {
    // 可能永远不等于 1.0f
}
```

**✅ 合规方案**
```c
for (int i = 0; i < 10; i++) {
    float f = i * 0.1f;
}
```

---

#### FLP32-C. 防止或检测数学函数中的域错误和范围错误

调用数学函数（`sqrt`、`log` 等）前需检查参数是否在有效域内。

**✅ 合规方案**
```c
#include <math.h>
#include <errno.h>

if (x < 0) {
    /* 域错误 */
} else {
    double result = sqrt(x);
}
```

## 06. 数组（ARR）

### 建议

#### ARR00-A. 理解数组是如何工作的

C 语言数组不进行边界检查，越界访问是未定义行为，必须由程序员手动确保边界安全。

---

#### ARR01-A. 不要对数组参数使用 sizeof

数组作为函数参数时会退化为指针，`sizeof` 返回指针大小而非数组大小。

**❌ 不合规示例**
```c
void process(int arr[]) {
    int size = sizeof(arr) / sizeof(arr[0]);  // 错误！arr 是指针
}
```

**✅ 合规方案**
```c
void process(int arr[], size_t n) {
    for (size_t i = 0; i < n; i++) { /* ... */ }
}
```

---

### 规则

#### ARR30-C. 不要在数组索引之前确认其有效范围

数组访问前必须验证索引在有效范围内。

**✅ 合规方案**
```c
if (index >= 0 && index < ARRAY_SIZE) {
    value = array[index];
}
```

---

#### ARR32-C. 确保不使用变长数组（VLA）的大小超过限制

VLA 分配在栈上，过大可能导致栈溢出。

---

#### ARR33-C. 确保拷贝操作不超出目标缓冲区

拷贝数据前检查目标缓冲区是否足够大。

**❌ 不合规示例**
```c
char dst[10];
char src[] = "This is a long string";
strcpy(dst, src);  // 缓冲区溢出
```

**✅ 合规方案**
```c
char dst[10];
strncpy(dst, src, sizeof(dst) - 1);
dst[sizeof(dst) - 1] = '\0';
```

---

#### ARR35-C. 不要将循环计数器越过数组末尾

即使不解引用，指针也不得越过数组末尾之后的位置（+1除外）。

---

#### ARR36-C. 不要对两个不同数组的指针做减法或比较

只有指向同一数组的两个指针之间的差值运算或比较才是合法的。

---

## 07. 字符串（STR）

### 建议

#### STR00-A. 以与其数据等效的方式表示字符串

字符串字面量是只读的，不应通过指向字面量的非 `const` 指针修改。

---

#### STR01-A. 对字符串操作采用一致的计划

确定是否使用 C 标准字符串函数、POSIX 字符串函数或 ISO TR 24731 安全字符串函数，并在整个项目中保持一致。

---

### 规则

#### STR30-C. 不要尝试修改字符串字面量

字符串字面量存储在只读内存中，修改它会导致未定义行为。

**❌ 不合规示例**
```c
char *str = "hello";
str[0] = 'H';  // 未定义行为，可能导致程序崩溃
```

**✅ 合规方案**
```c
char str[] = "hello";
str[0] = 'H';  // 合法，str 是可修改的数组
```

---

#### STR31-C. 确保字符串存储有足够空间

分配字符串空间时必须包含终止 NULL 字节的空间。

**❌ 不合规示例**
```c
char name[5];
strcpy(name, "Alice");  // "Alice" 需要 6 字节（含 '\0'），溢出
```

---

#### STR32-C. 不要向以 null 终止字符串为参数的函数传递非 null 终止的字符序列

许多字符串函数依赖 `'\0'` 来确定字符串结束位置，传入非 null 终止的序列会越界读取。

---

#### STR33-C. 使用多字节/宽字节字符时需注意大小

使用宽字符（`wchar_t`）或多字节字符时，字节数与字符数不同，需使用相应的宽字符函数。

---

#### STR35-C. 不要将超出目标长度的字符序列拷贝

使用 `strncpy`、`strlcpy` 等有长度限制的函数，并始终确保目标缓冲区有足够空间。

---

#### STR36-C. 不要把非字符数组指定为字符串 format 参数

使用 `printf` 等格式化函数时，格式字符串必须是以 `'\0'` 结尾的字符串。

---

## 08. 内存管理（MEM）

### 建议

#### MEM00-A. 为动态分配的对象分配并释放内存在同一模块，同一抽象层次

保持内存分配和释放在相同的代码层次，避免跨模块的所有权混乱。

---

#### MEM01-A. 释放内存后立即将指针设置为 NULL

`free()` 后立即将指针置 NULL，防止悬垂指针被误用。

**✅ 合规示例**
```c
free(ptr);
ptr = NULL;
```

---

### 规则

#### MEM30-C. 不要访问已释放的内存

释放内存后访问该内存是未定义行为（Use-After-Free）。

**❌ 不合规示例**
```c
free(ptr);
*ptr = 0;     // 未定义行为
printf("%d", *ptr);  // 未定义行为
```

---

#### MEM31-C. 每块动态分配的内存只释放一次

重复释放（Double-Free）是未定义行为，可能被利用为安全漏洞。

**✅ 合规方案**
```c
free(ptr);
ptr = NULL;  // 防止重复 free
```

---

#### MEM32-C. 检测并处理内存分配失败

`malloc`、`calloc`、`realloc` 在失败时返回 NULL，必须检查并处理。

**❌ 不合规示例**
```c
char *buf = malloc(size);
strcpy(buf, input);  // 未检查 malloc 返回值
```

**✅ 合规方案**
```c
char *buf = malloc(size);
if (buf == NULL) {
    /* 错误处理 */
    return ERROR_OUT_OF_MEMORY;
}
strcpy(buf, input);
```

---

#### MEM33-C. 只分配和释放相同类型的内存

使用正确的分配/释放配对：`malloc`/`free`、`new`/`delete`（C++）不得混用。

---

#### MEM34-C. 只释放动态分配的内存

不得对栈上对象、静态对象或字符串字面量调用 `free()`。

**❌ 不合规示例**
```c
int x = 5;
free(&x);      // 未定义行为

char str[] = "hello";
free(str);     // 未定义行为
```

---

#### MEM35-C. 为对象分配足够的内存

分配内存时必须考虑对象实际大小，使用 `sizeof` 确保正确。

**❌ 不合规示例**
```c
struct node *p = malloc(sizeof(struct node *));  // 分配了指针大小，而非结构体大小
```

**✅ 合规方案**
```c
struct node *p = malloc(sizeof(struct node));
```

---

## 09. 输入输出（FIO）

### 建议

#### FIO00-A. 谨慎使用格式化 IO 函数

格式化 IO 函数（`printf`、`scanf`、`sprintf` 等）存在格式字符串漏洞风险，不要将用户输入直接作为格式字符串。

**❌ 不合规示例**
```c
printf(user_input);    // 格式字符串注入漏洞！
sprintf(buf, input);   // 危险！
```

**✅ 合规方案**
```c
printf("%s", user_input);  // 用 %s 安全地输出字符串
```

---

#### FIO01-A. 谨慎使用 access() 以判断后续操作是否被允许

`access()` 与后续文件操作之间存在 TOCTOU（Time-of-Check Time-of-Use）竞争条件，不应依赖它来做安全决策。

---

### 规则

#### FIO30-C. 排除用户输入中的格式字符串

不得将用户输入直接作为格式字符串传给 `printf` 族函数。

---

#### FIO31-C. 不要同时以文本和二进制模式打开同一文件

在某些平台上，文本模式和二进制模式处理换行符等字符的方式不同，混用会导致数据损坏。

---

#### FIO32-C. 不要对设备文件执行操作

避免对 `/dev/null`、`/dev/random` 等特殊设备文件执行普通文件操作，可能引发意外行为。

---

#### FIO33-C. 检测和处理输入输出错误

对所有 IO 函数的返回值进行检查，处理可能的错误状态。

**✅ 合规方案**
```c
if (fgets(buf, sizeof(buf), stdin) == NULL) {
    if (feof(stdin)) { /* EOF */ }
    else { /* 读取错误 */ }
}
```

---

#### FIO34-C. 使用 int 来接收 getchar() 和 fgetc() 的返回值

这些函数返回 `int`（包含 EOF = -1），使用 `char` 接收会导致 EOF 检测失败。

**❌ 不合规示例**
```c
char c;
while ((c = getchar()) != EOF) { /* 若 char 为 unsigned，永远不等于 EOF */ }
```

**✅ 合规方案**
```c
int c;
while ((c = getchar()) != EOF) { /* 正确 */ }
```

---

#### FIO37-C. 不要假定 fgets 读到了完整行

`fgets` 在缓冲区满时会截断输入，不保证读到换行符。

---

#### FIO39-C. 在切换读写操作之间刷新流或重定位

在同一流上交替进行读写操作之前，需要调用 `fflush` 或文件定位函数。

---

#### FIO40-C. 在 fgets 返回 NULL 时重置 errno

`fgets` 返回 NULL 时，若需区分是 EOF 还是错误，需在调用前将 `errno` 置零。

---

#### FIO41-C. 在 scanf 调用中不使用带有副作用的参数

`scanf` 函数不保证参数求值顺序，不得在参数中使用有副作用的表达式。

---

#### FIO42-C. 确保文件在退出程序前被关闭

每个通过 `fopen` 打开的文件，必须在使用完毕后调用 `fclose`。

---

#### FIO44-C. 只在 fsetpos 中使用 fgetpos 返回的值

`fpos_t` 类型的值是不透明的，不应手动修改，只能用 `fgetpos` 获取后传给 `fsetpos`。

---

## 10. 临时文件（TMP）

### 规则

#### TMP30-C. 安全地创建和使用临时文件

使用 `tmpfile()` 或 `mkstemp()`（POSIX）创建临时文件，避免竞争条件。

**❌ 不合规示例**
```c
// tmpnam 存在 TOCTOU 竞争条件
char *name = tmpnam(NULL);
FILE *f = fopen(name, "w");
```

**✅ 合规方案（POSIX）**
```c
#include <stdlib.h>
char template[] = "/tmp/tmpXXXXXX";
int fd = mkstemp(template);
if (fd == -1) { /* 错误处理 */ }
```

---

#### TMP31-C. 及时删除临时文件

确保临时文件在使用完毕后被删除，防止信息泄露。

---

#### TMP32-C. 确保临时文件的安全使用

临时文件在创建时应指定严格权限，防止其他用户访问。

---

#### TMP33-C. 不要缓存 tmpnam、tempnam 等产生的文件名

这些函数的返回值不具有唯一性保证，重复使用可能导致竞争条件。

---

## 11. 环境（ENV）

### 规则

#### ENV30-C. 不要修改 getenv 返回的字符串

`getenv()` 返回的字符串指向静态存储区，修改它会导致未定义行为。

**❌ 不合规示例**
```c
char *path = getenv("PATH");
path[0] = '/';  // 未定义行为
```

**✅ 合规方案**
```c
const char *path = getenv("PATH");
char *path_copy = strdup(path);  // 复制后再修改
```

---

#### ENV31-C. 在调用 setenv/putenv/unsetenv 后不要依赖 environ 变量

调用这些函数后，之前保存的 `environ` 指针可能失效。

---

#### ENV32-C. 在 atexit 处理器中不要使用 exit

在 `atexit` 注册的函数中调用 `exit()` 会导致未定义行为（无限循环或其他问题）。

---

#### ENV33-C. 不要调用 system()

`system()` 可能被路径注入或命令注入攻击利用，应使用 `execve()` 等更安全的替代方案。

---

## 12. 信号（SIG）

### 规则

#### SIG30-C. 在信号处理函数中只调用异步安全的函数

在信号处理函数中只能调用异步信号安全（async-signal-safe）的函数，否则可能导致死锁或数据损坏。

**❌ 不合规示例**
```c
void handler(int sig) {
    printf("Signal %d\n", sig);  // printf 不是异步安全的
    exit(1);                      // exit 也不是异步安全的（但 _Exit 是）
}
```

**✅ 合规方案**
```c
volatile sig_atomic_t flag = 0;

void handler(int sig) {
    flag = 1;  // 只修改 sig_atomic_t 类型的标志
}
```

---

#### SIG31-C. 不要从信号处理函数中访问或修改共享对象

信号处理函数与主程序共享对象时，必须保证访问的原子性，仅使用 `volatile sig_atomic_t` 类型。

---

#### SIG32-C. 不要在 SIGFPE、SIGILL 或 SIGSEGV 信号处理后返回

这些信号产生于程序本身，处理后从信号处理函数返回会导致未定义行为。

---

#### SIG33-C. 不要递归调用 raise 或 abort

在信号处理函数中不得递归地触发同一信号。

---

#### SIG34-C. 在中断行为之前不要调用 signal

在 POSIX 系统上，调用 `signal()` 的行为在信号处理完成前是不可预期的，应使用 `sigaction()` 代替。

---

## 13. 杂项（MSC）

### 建议

#### MSC00-A. 在切换的每个 case 都要加注释

每个 `switch` 语句的 `case` 分支都应明确注释是否为故意穿透（fall-through），否则可能是遗漏的 `break`。

---

#### MSC01-A. 力求代码逻辑上的自洽

避免代码中出现逻辑自相矛盾的情况（如永真/永假条件）。

---

### 规则

#### MSC30-C. 不要使用 rand() 函数生成伪随机数

`rand()` 生成的随机数质量较差，不得用于安全相关目的（如密码学、令牌生成）。

**✅ 合规方案（POSIX）**
```c
#include <stdlib.h>
// 使用 /dev/urandom 或 OS 提供的加密安全随机数
int fd = open("/dev/urandom", O_RDONLY);
read(fd, &value, sizeof(value));
```

---

#### MSC31-C. 确保 main 函数返回类型为 int

C99 标准要求 `main()` 的返回类型必须是 `int`，不能是 `void`。

**❌ 不合规示例**
```c
void main(void) { /* ... */ }
```

**✅ 合规方案**
```c
int main(void) {
    return 0;
}
```

---

## 50. POSIX 扩展

### 规则

#### POS30-C. 使用 readlink 的正确方法

`readlink()` 不会在缓冲区末尾添加 `'\0'`，必须手动添加终止符。

**✅ 合规示例**
```c
char buf[PATH_MAX + 1];
ssize_t len = readlink(path, buf, PATH_MAX);
if (len != -1) {
    buf[len] = '\0';
}
```

---

#### POS33-C. 不要使用 vfork

`vfork()` 的语义非常脆弱，在很多情况下行为未定义，应使用 `fork()` 代替。

---

#### POS35-C. 避免文件操作的竞争条件

文件的创建、打开、权限检查之间存在 TOCTOU 竞争条件，使用 `O_CREAT|O_EXCL` 等标志避免。

**✅ 合规方案**
```c
int fd = open(path, O_CREAT | O_EXCL | O_WRONLY, 0600);
if (fd == -1) {
    if (errno == EEXIST) { /* 文件已存在 */ }
    else { /* 其他错误 */ }
}
```

---

#### POS36-C. 正确使用 syslog

不要将用户输入直接作为 `syslog` 的格式字符串，防止格式字符串注入。

**❌ 不合规示例**
```c
syslog(LOG_INFO, user_input);  // 格式字符串注入
```

**✅ 合规方案**
```c
syslog(LOG_INFO, "%s", user_input);
```

---

#### POS37-C. 确保 getpwuid_r 和 getgrgid_r 的返回值正确

这些线程安全版本的函数返回方式与旧版不同，需正确处理其返回值和指针。
