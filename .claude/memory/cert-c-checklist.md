# CERT C 安全编码检查清单（项目要求）

**所有新生成或修改的 C 代码必须通过此清单检查。** 完整清单文档位于 [.claude/skills/CERT_C_CheckList.md](.claude/skills/CERT_C_CheckList.md)，基于卡内基梅隆大学 SEI/CERT C 安全编码标准（N1255，2007年9月10日）。

## 规则体系

- **规则（Rules）**：必须遵守，违反将导致可利用的安全漏洞
- **建议（Recommendations）**：推荐遵守，改善系统安全性

标识符格式：`XXX##-A/C`（A=建议，C=规则）。优先级 P1-P3，等级 L1-L3。

## 13 大规则类别

### 01. 预处理器（PRE）
- PRE00-A: 优先使用内联函数替代宏
- PRE01-A: 宏定义中对变量名使用括号 `((I) * (I))`
- PRE02-A: 函数式宏展开结果必须用括号括起
- PRE03-A: 通过 `(func)()` 防止误调用宏
- PRE30-C: 不要通过 `##` 拼接创建通用字符名

### 02. 声明与初始化（DCL）
- DCL00-A: 用 `const` 限定不变对象
- DCL01-A: 不要在子作用域中重用变量名（shadowing）
- DCL04-A: 每次声明只声明一个变量
- DCL30-C: 不得返回局部变量的指针/引用
- DCL31-C: 使用前必须先声明标识符（禁止隐式声明）
- DCL32-C: 外部链接标识符在整个程序中必须唯一

### 03. 表达式（EXP）
- EXP00-A: 使用括号明确运算符优先级 `if ((a & b) == 0)`
- EXP01-A: 不要对指针取 `sizeof`，返回指针大小而非对象大小
- EXP30-C: 不要依赖序列点之间的求值顺序（`i++ + i++` 是未定义行为）
- EXP33-C: 不要读取未初始化的内存
- EXP34-C: **解引用指针前必须检查是否为 NULL**

### 04. 整数（INT）
- INT00-A: 使用固定宽度类型（`int32_t`、`uint64_t` 等）
- INT01-A: 使用 `size_t` 或 `rsize_t` 表示对象大小
- INT30-C: **确保无符号整数运算不发生回绕**
- INT31-C: 确保整数转换不会丢失或解释错误
- INT32-C: **确保有符号整数操作不溢出**（未定义行为）
- INT33-C: **除法和取模前检查除数为零** 及 `INT_MIN / -1`

### 05. 浮点数（FLP）
- FLP30-C: **不要在循环计数器中使用浮点变量**
- FLP32-C: 调用数学函数前检查参数域（`sqrt` 负数、`log` 非正数）

### 06. 数组（ARR）
- ARR00-A: 理解数组不进行边界检查，手动确保安全
- ARR01-A: 不要对数组参数使用 `sizeof`（退化指针）
- ARR30-C: **数组索引访问前必须验证范围**
- ARR33-C: **拷贝操作前确保目标缓冲区足够大**
- ARR35-C: 不要将循环计数器越过数组末尾

### 07. 字符串（STR）
- STR30-C: **不要修改字符串字面量**（只读内存）
- STR31-C: **字符串存储必须包含终止 NULL 字节空间**
- STR32-C: 不要向字符串函数传递非 null 终止的字符序列
- STR35-C: 使用 `strncpy`/`strlcpy` 等有长度限制的函数

### 08. 内存管理（MEM）
- MEM00-A: 分配和释放内存在同一模块、同一抽象层次
- MEM01-A: **释放内存后立即将指针设置为 NULL**
- MEM30-C: **禁止访问已释放的内存（Use-After-Free）**
- MEM31-C: **每块动态分配的内存只释放一次（禁止 Double-Free）**
- MEM32-C: **必须检查 `malloc`/`calloc`/`realloc` 返回值是否为 NULL**
- MEM34-C: 只释放动态分配的内存（不得 `free` 栈上对象）
- MEM35-C: 分配内存时使用 `sizeof` 确保大小正确

### 09. 输入输出（FIO）
- FIO00-A: 谨慎使用格式化 IO，不要将用户输入直接作为格式字符串
- FIO30-C: **禁止用户输入作为格式字符串**（`printf(user_input)`——格式字符串注入）
- FIO33-C: 检测和处理所有 IO 函数的返回值错误
- FIO34-C: **使用 `int` 接收 `getchar()`/`fgetc()` 返回值**（char 无法区分 EOF）
- FIO42-C: 确保文件在退出程序前被关闭

### 10. 临时文件（TMP）
- TMP30-C: 使用 `tmpfile()` 或 `mkstemp()` 安全创建临时文件（避免 TOCTOU）

### 11. 环境（ENV）
- ENV30-C: 不要修改 `getenv()` 返回的字符串
- ENV33-C: **禁止调用 `system()`**（命令注入风险）

### 12. 信号（SIG）
- SIG30-C: **信号处理函数中只调用异步安全函数**
- SIG31-C: 不在信号处理函数中访问共享对象（仅用 `volatile sig_atomic_t`）
- SIG34-C: 使用 `sigaction()` 代替 `signal()`

### 13. 杂项（MSC）
- MSC00-A: switch 的每个 case 加注释（穿透/break）
- MSC30-C: **禁止用 `rand()` 生成安全相关随机数**（密码学弱点）
- MSC31-C: `main()` 返回类型必须为 `int`

## 嵌入式系统特别关注项（高优先级）

以下规则对 FoxBMS 2 嵌入式平台（ARM Cortex-R5F）尤为重要：

| 编号 | 规则 | 风险类型 | 等级 |
|------|------|---------|------|
| EXP34-C | 空指针解引用前检查 | 崩溃/任意代码执行 | L3 |
| INT32-C | 有符号整数溢出检查 | 整数溢出漏洞 | L2 |
| INT30-C | 无符号整数回绕检查 | 整数回绕漏洞 | L2 |
| INT33-C | 除零检查 | 未定义行为 | L2 |
| MEM30-C | 禁止访问已释放内存 | UAF 漏洞 | L1 |
| MEM31-C | 禁止重复释放内存 | Double-Free 漏洞 | L1 |
| MEM32-C | 检查内存分配失败 | 空指针解引用 | L2 |
| STR30-C | 禁止修改字符串字面量 | 崩溃/未定义行为 | L2 |
| STR31-C | 字符串缓冲区须含终止符空间 | 缓冲区溢出 | L1 |
| ARR30-C | 数组索引越界检查 | 缓冲区溢出 | L1 |
| ARR33-C | 拷贝不超出目标缓冲区 | 缓冲区溢出 | L1 |
| FIO30-C | 禁止用户输入作为格式字符串 | 格式字符串攻击 | L2 |
| SIG30-C | 信号处理函数只调用异步安全函数 | 死锁/数据损坏 | L1 |
| ENV33-C | 禁止调用 system() | 命令注入 | L2 |
| MSC30-C | 禁止用 rand() 做安全随机数 | 密码学弱点 | L2 |

**Why:** FoxBMS 2 是汽车级 BMS 嵌入式系统，运行于 TI TMS570LC4357 (ARM Cortex-R5F)。CERT C 编码标准由美国国防部资助、卡内基梅隆大学 SEI 开发，是嵌入式 C 语言安全编码的国际权威标准。与 MISRA C:2012 互补——MISRA C 侧重汽车行业代码质量，CERT C 侧重安全漏洞防护。

**How to apply:** 每次生成或修改 C 代码后，按 13 大类别逐项对照检查。优先确保标注 **粗体** 的规则无违规，特别关注嵌入式系统特别关注项。发现违规立即修正后再提交。建议结合静态分析工具（Cppcheck、Clang Static Analyzer）自动化检测。**检查完成后必须生成代码审查结果报告**，存放于源文件所在目录的 `code-review-results/` 文件夹中。
